# ADR-0006: Convenção de nomenclatura — Handler vs. Dispatcher

Data: 2026-08-09
Status: Aceito

## Contexto

Os arquivos em `agents/` usavam o sufixo "Agent" para papéis muito diferentes:
classes que executam uma operação já decidida (create, update, delete, query,
list, subscribe) e uma classe que decide para onde encaminhar a mensagem
(route). Chamar os dois de "Agent" sugere autonomia de decisão que só o
segundo grupo tem — o primeiro grupo não decide nada, só executa.

## Decisão

Adotar dois sufixos, conforme o papel real de cada arquivo:
- **Handler**: recebe uma operação já determinada e executa o tratamento
  dela (CreateHandler, UpdateHandler, DeleteHandler, ListHandler,
  QueryHandler, SubscribeHandler, AnalyzeHandler).
- **Dispatcher**: decide qual handler deve receber a mensagem e encaminha
  para ele (RouteDispatcher).

`registry.py` mantém seu nome — é uma estrutura de dados (mapa operação →
classe), não uma classe que processa mensagens, então não se encaixa em
nenhum dos dois sufixos.

## Alternativas consideradas

- **Manter o sufixo "Agent" para tudo** — descartada: perpetua a confusão
  conceitual que motivou a checagem terminológica logo no início do
  refactoring (ver conversa sobre "o que é realmente um agente").
- **Usar "Function" em vez de "Handler"** — descartada: "Function" sugere uma
  função pura sem estado; as classes atuais recebem dependências por
  construtor (FiwareClient) e têm método `process`, então "Handler" descreve
  melhor a forma real do código sem exigir reescrever a estrutura de classes.
- **Usar "Dispatcher" para todos os executores também** — descartada: geraria
  confusão com o único Dispatcher real (RouteDispatcher), que tem uma
  responsabilidade genuinamente diferente (decidir destino, não executar).

## Consequências

**Positivas:**
- O nome do arquivo já comunica a responsabilidade, sem precisar ler o
  código para saber se algo decide ou executa.
- Alinha a nomenclatura do código com a decisão de arquitetura do ADR-0001
  (agentes de domínio não têm autonomia de decisão própria).

**Negativas / trade-offs aceitos:**
- Renomear arquivos existentes exige atualizar todos os imports e os testes
  que referenciam as classes antigas — trabalho mecânico, mas com risco de
  esquecer alguma referência (mitigável rodando a suíte de testes completa
  após a renomeação, antes de dar como concluído).
