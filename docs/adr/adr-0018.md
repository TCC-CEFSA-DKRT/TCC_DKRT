# ADR-0018: AWS Academy Learner Lab descontinuada — `environments/academy` renomeado para `environments/homolog`

Data: 2026-09-15
Status: Parcialmente substituído por ADR-0021 (a descontinuação da Academy permanece; a arquitetura EC2 da homologação não)

## Contexto

Toda a Fase 9 (`.cursor/specs/fase9.spec.md`) e as ADRs 0013/0014/0015 foram desenhadas em
torno das restrições concretas da **AWS Academy Learner Lab**: sem `iam:CreateRole`
(`LabRole`/`LabInstanceProfile` pré-existentes), crédito total de US$ 100 por aluno, sessão
efêmera (recursos somem quando a sessão do laboratório encerra), e região restrita a
`us-east-1`/`us-west-2`. `infra/terraform/environments/academy/` foi escrito inteiramente sob
essas restrições.

O usuário decidiu que **a conta AWS Academy Learner Lab não vai mais ser usada neste
projeto** — não é uma pausa, é uma descontinuação. O motivo prático: o TCC precisa de um
ambiente que sobreviva além do fim de uma sessão de laboratório, tanto para os testes
recorrentes durante o desenvolvimento quanto para a apresentação final à banca. A intenção
declarada é rodar em três lugares com papéis diferentes: **local** (desenvolvimento e testes,
já coberto por `docker-compose.yml` + processo Python direto — não afetado por esta ADR),
**homologação na nuvem** (ambiente de teste/validação antes da apresentação, tema desta ADR)
e **produção** (o que é efetivamente mostrado como produto final — `environments/production`,
já migrado para Lambda pela ADR-0017, também não afetado por esta ADR).

Perguntado sobre qual arquitetura usar para a homologação já que a Academy não é mais opção,
o usuário escolheu **reaproveitar a mesma arquitetura EC2** que já existia em
`environments/academy` (Ollama numa instância GPU + API/worker em EC2, ADR-0013/ADR-0015),
só trocando a conta de destino — não a stack Lambda/ALB da produção (ADR-0017), que exigiria
domínio real + certificado ACM, e não uma terceira arquitetura nova a desenhar do zero. Na
mesma conversa, confirmou que a conta AWS real para essa homologação **ainda não existe**
("ainda não, mas vai ter em breve") — esta ADR já deixa o Terraform pronto para quando ela
existir, sem bloquear nisso.

## Decisão

1. **Renomear `infra/terraform/environments/academy/` para `infra/terraform/environments/homolog/`**,
   mantendo a arquitetura EC2 (`modules/compute`, `modules/network`, `modules/database`,
   `modules/queue`, `modules/secrets`) inteiramente igual — nenhuma mudança de topologia,
   só de conta/identidade do ambiente.
2. **Remover as três dependências específicas da AWS Academy Learner Lab** do novo
   `environments/homolog/`, já que uma conta real não tem essas restrições:
   - `create_role` passa de `false` para `true` — o ambiente agora cria sua própria IAM role
     via `modules/compute` (o padrão `create_role`/`existing_instance_profile_name` já era
     genérico no módulo desde a Fase 9 original; só o valor passado muda). A referência ao
     `data "aws_iam_instance_profile" "lab"` (`LabInstanceProfile`) foi removida.
   - A validação de região restrita a `us-east-1`/`us-west-2` foi removida de
     `variable "region"` — uma conta real não tem essa limitação do Learner Lab.
   - `name_prefix` (`auditor-academy` → `auditor-homolog`) e a tag `Environment`
     (`academy` → `homolog`) atualizados para refletir a identidade nova.
3. **`environments/academy/` não foi excluído** (não é possível excluir arquivos no device
   nesta sessão — bridge sem `device_bash` — ver limitação abaixo), mas todo o seu conteúdo
   foi reduzido a um comentário de uma linha apontando para `environments/homolog/` e para
   esta ADR, mais um `MOVED.md` explicando a descontinuação.
4. **`.github/workflows/terraform-and-audit.yml`** também precisa apontar para
   `environments/homolog` (working-directory, nome dos jobs, `environment: homolog-apply`,
   chave do state) — o conteúdo já foi preparado e validado como YAML, mas **não pôde ser
   commitado**: arquivos de workflow do GitHub Actions são bloqueados para escrita remota
   pela própria ferramenta usada nesta sessão (proteção de segurança, não um erro transitório).
   O usuário recebeu o arquivo pronto para aplicar manualmente.
5. **`environments/production` (ADR-0017, Lambda/ALB) não muda em nada** — esta ADR é só
   sobre o ambiente que substitui a Academy.

## Alternativas consideradas

- **Manter `environments/academy` como está, só documentando que está obsoleto** — descartada:
  o nome do diretório e das variáveis (`auditor-academy`, `LabInstanceProfile`) ativamente
  confunde quem for aplicar isso numa conta real depois; a AWS rejeitaria o `apply` mesmo
  assim (`LabInstanceProfile` só existe em contas Academy), então manter o nome sem corrigir
  o conteúdo seria pior que só corrigir wording sem trocar a topologia.
- **Migrar já para a mesma stack Lambda/ALB da produção (ADR-0017) em vez de reaproveitar o
  EC2** — descartada pelo usuário: exigiria domínio real + certificado ACM + CloudFront desde
  já só para homologar, antes mesmo de ter a conta provisionada; a arquitetura EC2 já está
  escrita, testada por inspeção estrutural, e mais barata/simples para um ambiente de
  homologação que não precisa imitar produção 1:1, só validar que o sistema roda de ponta a
  ponta na nuvem antes da apresentação.
- **Desenhar uma terceira arquitetura nova (containers em VM/ECS, nem o EC2 "cru" nem o
  Lambda)** — descartada: maior esforço, sem necessidade concreta identificada, e joga fora
  trabalho já validado (ADR-0013/ADR-0015) sem motivo.

## Consequências

**Positivas:**
- `environments/homolog` está pronto para um `terraform apply` real assim que a conta AWS
  existir — nenhum trabalho de infraestrutura bloqueando esse próximo passo.
- Reaproveita integralmente o raciocínio já validado de custo/GPU (ADR-0013/ADR-0015) — não
  precisa refazer a decisão Ollama-EC2-com-GPU do zero.
- `environments/production` continua intocado — esta ADR não introduz risco nenhum ali.

**Negativas / trade-offs aceitos:**
- `environments/academy/` continua existindo no repositório como um diretório de arquivos
  inertes (não pôde ser excluído) — leve poluição, mitigada pelo `MOVED.md` e pelos stubs de
  uma linha em cada arquivo.
- `.github/workflows/terraform-and-audit.yml` está desatualizado (ainda referencia `academy`)
  até o usuário aplicar manualmente o arquivo entregue — enquanto isso, um `terraform apply`
  disparado pelo workflow (`workflow_dispatch`) apontaria para um ambiente que só tem o stub
  de uma linha, e falharia explicitamente (sem `provider`/`backend` configurado) em vez de
  aplicar algo errado — falha seca é o comportamento seguro aqui, mas é uma lacuna até a
  correção manual.
- `.cursor/specs/fase9.spec.md` continua descrevendo o cenário Academy em detalhe (seções 1,
  3, 6, 9) — preservado por valor histórico (mesmo raciocínio das ADRs 0000-0012, ver
  `docs/adr/README.md`), com uma nota apontando para esta ADR, em vez de reescrito por
  completo. O `plano_refatoracao_v3.md` (Parte I, 1.1) também ainda descreve as restrições do
  Academy em detalhe — não foi atualizado nesta ADR; fica como um follow-up separado, dado o
  tamanho da reescrita que a Parte I inteira exigiria.
- Nenhum `terraform apply` real foi (nem pôde ser) testado contra a conta de homologação —
  ela ainda não existe. O que esta ADR garante é que o código está pronto e sintaticamente
  válido (`python-hcl2`) para quando existir, não que já foi validado ao vivo.
