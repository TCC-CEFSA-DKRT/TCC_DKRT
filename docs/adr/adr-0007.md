# ADR-0007: RouteAgent vira RouteDispatcher (fallback determinístico)

Data: 2026-08-09
Status: Aceito

## Contexto

`RouteAgent` classifica intenção por palavra-chave (regex/keywords), sem usar
o SLM. O ADR-0001 já havia decidido que ele não deveria ser a via principal
de decisão — o SLM é. Faltava decidir formalmente seu papel remanescente.

## Decisão

`route.py` é renomeado para `dispatcher.py` (classe `RouteDispatcher`),
mantido exclusivamente como fallback determinístico: só é acionado quando o
Ollama está indisponível ou o parsing estruturado do SLM falha (ver Bloco 2
do plano — parsing JSON nativo do Ollama). Em operação normal, quem decide a
rota é o `IntentRouter` com base na classificação do SLM.

## Alternativas consideradas

- **Remover o RouteAgent completamente** — descartada: um fallback
  determinístico é uma rede de segurança legítima quando o SLM local está
  indisponível (não é incomum em ambiente de desenvolvimento com Ollama
  rodando localmente); eliminar isso faria o sistema falhar por completo
  nesses casos, em vez de degradar graciosamente.
- **Manter como via de decisão primária, em paralelo ao SLM** — descartada:
  contradiz a proposta central do projeto (interpretação via IA) e o próprio
  ADR-0001.

## Consequências

**Positivas:**
- Sistema continua funcional (com precisão reduzida) mesmo se o SLM local
  cair — importante para demonstrações ao vivo, onde falha de ambiente é um
  risco real.
- Papel do arquivo fica sem ambiguidade: é explicitamente um fallback, não
  uma segunda via de decisão "oficial".

**Negativas / trade-offs aceitos:**
- Mantém a lógica de palavras-chave em português como código vivo, que
  precisa ser atualizada manualmente se o vocabulário de operações mudar
  (ex: quando `history` for adicionado no Bloco 5).
